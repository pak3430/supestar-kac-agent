# 이 구조를 쉽게 설명하는 방법

## 한 문장 설명

수페스타는 ESG 지식을 저장해 둔 챗봇이 아니라, 로컬 Qwen이 연결된 지식을 관찰하고 필요한 원자 스킬을 실제 실행한 뒤 근거가 검증된 문장만 답하는 에이전트입니다.

## 30초 설명

일반 챗봇은 질문을 받으면 곧바로 문장을 만듭니다. 수페스타는 먼저 질문에서 관련 개념을 찾고, CCS에서 그 개념과 관계를 관찰합니다. 그런 다음 Local Qwen이 필요한 KAC 스킬을 고릅니다. 스킬은 실제 코드로 실행되고 Scope 분류나 절차 판정 같은 결과를 만듭니다. Qwen은 그 결과를 다시 보고 다음 행동을 정합니다. 마지막에는 검증기가 관찰한 근거와 출처가 연결된 문장만 승인합니다.

## “Qwen이 스킬을 실행하나요?”에 대한 답

정확히는 Qwen이 스킬 호출을 **선택하고 요청**하며, 안전한 Runtime이 입력 계약을 검사한 뒤 스킬 코드를 **실행**합니다.

Qwen에게 서버 코드를 마음대로 실행할 권한을 주지 않습니다. 실제 Agent 시스템에서 모델은 판단 주체, Runtime은 실행 주체, Verifier는 승인 주체로 분리하는 편이 안전합니다.

## “JSON을 읽는 RAG 아닌가요?”에 대한 답

JSON은 저장 형식일 뿐입니다. 단순히 JSON 문장을 검색해 답하는 구조라면 RAG에 가깝습니다. 수페스타는 검색 뒤에 끝나지 않습니다.

- Qwen이 다음 관찰을 선택합니다.
- 관계 edge를 따라 새 지식을 봅니다.
- Stage에서 파생된 원자 스킬을 호출합니다.
- 스킬 실행 결과가 새 Observation이 됩니다.
- 그 결과에 따라 다음 행동이 달라집니다.
- 근거 없는 최종 문장은 차단됩니다.

따라서 “지식 데이터만 가진 챗봇”보다 **지식행동사슬로 나온 스킬을 실행하는 챗봇** 방향에 가깝습니다.

## 화면에서 보여줄 순서

1. 질문을 입력한다.
2. Local Qwen 모델명과 loopback 배지를 보여준다.
3. Qwen이 선택한 `observe_concept`를 보여준다.
4. 연결 edge를 확장하는 장면을 보여준다.
5. 원자 스킬명과 실제 입력을 보여준다.
6. SkillRun의 `PROCEED/REVIEW/STOP`을 보여준다.
7. 일부러 차단된 후보와 누락 근거를 보여준다.
8. Qwen이 추가 관찰로 스스로 보완하는 장면을 보여준다.
9. Verifier `PASS`와 최종 답변을 보여준다.
10. run JSON의 model digest, skill run ID, source ref를 보여준다.

## 과장하지 말아야 할 표현

- “AI가 모든 ESG 지식을 안다”라고 하지 않습니다.
- “Qwen이 운영체제에서 임의 코드를 실행한다”라고 하지 않습니다.
- “Scope 1 답이 나왔으니 실제 배출량까지 인증됐다”라고 하지 않습니다.
- “Skill PROCEED가 실제 탄소감축 성과를 증명한다”라고 하지 않습니다.
- “인터넷을 물리적으로 차단한 패킷 캡처까지 완료했다”라고 하지 않습니다.

## 가장 정확한 결론

이 프로젝트는 Local Qwen이 CCS Observation을 바탕으로 Stage 유래 KAC 원자 스킬을 선택·실행하고, 실행 결과를 다시 관찰해 다음 행동을 정하며, 검증된 claim만 공개하는 제한형 자율 에이전트 Runtime입니다.
