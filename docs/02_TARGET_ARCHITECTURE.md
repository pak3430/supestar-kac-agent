# 목표 아키텍처

```text
┌──────────────────┐
│ 사용자 질문       │
└────────┬─────────┘
         ▼
┌──────────────────┐
│ Local Qwen Planner│
│ 다음 도구 선택     │
└────────┬─────────┘
         ▼
┌─────────────────────────────────────────────┐
│ 허용된 도구 레지스트리                       │
│ observe_concept · expand_relations           │
│ invoke_kac_skill · request_missing_evidence  │
│ submit_answer_candidate                      │
└────────┬────────────────────────────────────┘
         ▼
┌──────────────────┐     ┌────────────────────┐
│ CCS 지식·관계 환경│     │ KAC 원자 Skill Runtime│
└────────┬─────────┘     └─────────┬──────────┘
         └──────────┬───────────────┘
                    ▼
             Observation 반환
                    │
                    └──────→ Local Qwen Planner 반복
                                   │
                                   ▼
                         근거·경계 검증기
                                   │
                    ┌──────────────┴─────────────┐
                    ▼                            ▼
              최종 답변 승인                보완/중단
```

## 책임 분리

| 구성요소 | 책임 | 하지 않는 것 |
|---|---|---|
| Local Qwen Planner | 다음 관찰·Skill 행동 선택 | 출처·관계·판정 임의 생성 |
| CCS 환경 | 개념·관계·출처 Observation 제공 | 질문별 경로 지정 |
| KAC Skill Runtime | 구조화된 도메인 행동 실행 | 자유문장으로 규칙 변경 |
| Orchestrator | 호출 검증·예산·반복·기록 | 도메인 정답 경로 하드코딩 |
| Verifier | 관찰 근거·anchor·claim 검사 | 답변 대신 생성 |
| Renderer | 검증된 결과 표시 | 내부 추론 전체 공개 |

## 핵심 차이

v2의 `질문 키워드 → 고정 route`를 제거합니다. v3에서는 모든 등록 Skill을 도구 레지스트리에서 발견할 수 있고, Qwen이 현재 Observation을 바탕으로 다음 도구를 선택합니다. 오케스트레이터는 선택의 허용 여부만 판정합니다.
